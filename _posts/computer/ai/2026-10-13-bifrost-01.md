## AI - 大模型代理（bifrost）

我们的目标

1. 把多家的llm厂商进行收拢，减少业务层变动，增加token安全。
2. AI Agent多“设备USB”的远程接入。

### bifrost VS 其他

我更倾向于go开发的llm代理，只需要一个可执行文件就行（服务端的启动程序），无需过多依赖（有些依赖库的版本，例如node、python）安装。

- bifrost 

  > 资料：https://docs.getbifrost.ai 、 https://github.com/maximhq/bifrost/releases

  高性能通用LLM网关、 5000 RPS（厂商数据），基础版（免费版）和企业版（完整版）。

  选择原因：基础版够用

- GoModel

  > 资料： https://github.com/ENTERPILOT/GoModel

  我在使用的时候，model的alias用了一段时间，升级到了virtual models；但是我进行deepseek的Anthropic当作web_search工具时，由于参数未透传到底层，才放弃使用的。

- CLIProxyAPI

  > 资料： https://github.com/router-for-me/CLIProxyAPI

  我用它代替了GoModel后，用了一段时间。

- liteLLM

  未使用

#### 服务端

```dockerfile
FROM maximhq/bifrost:v2.2.6

USER root

# ============================================================
# 第 1 层：更换 Alpine 镜像源（加速 apk 下载）
# ============================================================
RUN sed -i 's/dl-cdn.alpinelinux.org/mirrors.ustc.edu.cn/g' /etc/apk/repositories

# ============================================================
# 第 2 层：安装 Node.js + Python3 + pip + 编译工具
# 说明：uvx 需要系统 Python 解释器，build-base 用于编译 Python 原生扩展
# ============================================================
RUN --mount=type=cache,target=/var/cache/apk \
    apk add --no-cache \
    nodejs npm \
    python3 python3-dev py3-pip \
    build-base libffi-dev openssl-dev \
    && node --version \
    && python3 --version \
    && pip3 --version

# ============================================================
# 第 3 层：安装 uv / uvx（两种方式任选其一）
# ============================================================

# --- 方式 A（推荐）：直接从官方镜像 COPY 二进制，最快最干净 ---
COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /usr/local/bin/

# --- 方式 B（备选）：如果 COPY 方式不可用，用 Alpine 包管理器 ---
# RUN apk add --no-cache uv

# 验证 uvx 可用
RUN uvx --version

# ============================================================
# 第 4 层：设置 npm 淘宝镜像源 + 安装全局 Node MCP 服务器
# ============================================================
RUN npm config set registry https://registry.npmmirror.com

RUN --mount=type=cache,target=/root/.npm \
    npm install -g @benborla29/mcp-server-mysql

# ============================================================
# 第 5 层：验证 Python MCP 服务器可通过 uvx 拉起（可选预装）
# uvx 是懒加载的，第一次调用会自动下载，这里不做预装
# ============================================================


USER 1000:0
WORKDIR /app

ENTRYPOINT ["/app/docker-entrypoint.sh"]
CMD ["/app/main"]
```

```shell
# 构建
docker build -t bifrost-mcp-server:2.2.6 .
# 如果dockerfile文件名为 bifrost-mcp-server.docker
# docker build -t bifrost-mcp-server:2.2.6 -f bifrost-mcp-server.docker . 
```

```shell
# 启动，最好持久化到本地，方便重建container时数据不丢失
# 不用config.json文件控制，全部都存储到sqlite数据库中。
docker run -d \
  --name bifrost-mcp \
  -p 8081:8080 \
  -v /Users/wangfuyu/Project/docker_data/bifrost_mcp_data/data:/app/data \
  --add-host=host.docker.internal:host-gateway \
  -e ALLOW_INSERT_OPERATION=false \
  -e ALLOW_UPDATE_OPERATION=false \
  -e ALLOW_DELETE_OPERATION=false \
  -e BIFROST_SETUP_TOKEN=8a7be94c-b845-470b-b18c-dbb14c94f9e6.100 \
  bifrost-mcp-server:2.2.6
```

以上安装启动完成，进行配置一个宿主机的mysql和一个邮箱功能。

### 结论

1. 对多个大模型进行统一管理，方便切换。
2. 对待使用tool，也可以一步到位，比如search、代发邮件、统一文件资源中心等功能，直接使用mcp让模型集成回答问题。
3. 对于单独接入MCP的，使用别的LLM，那么可能返回的tool不是想要的，需要用程序写好返回tool的参数。
4. bifrost 部署需要联网，可以自己对出网控制，允许请求他们官方的数据。
